# AI Agent Evaluation Pipeline

A robust, closed-loop evaluation system for AI agents utilizing Node.js, an Express API, MySQL with raw parameterized queries, and a React dashboard.

## Architecture Overview
The system follows a 5-stage pipeline for automated metrics generation:
1. **Ingest**: Logs conversations in a scalable MySQL structure.
2. **Evaluate**: A single GPT-4o call scores all four dimensions (LLM Judge, Coherence, Heuristic, Tool Call) using extracted objective facts.
3. **Reconcile**: Confidence-weighted comparison of automated evaluations versus human annotations, with annotator disagreement detection and tiebreaker resolution.
4. **Suggest**: Aggregates failure patterns and proposes prompt modifications and tool schema improvements dynamically generated by GPT-4o.
5. **Meta-Evaluate**: Tracks evaluator accuracy (precision/recall/F1), detects blind spots, computes drift corrections, and auto-applies them to future evaluations.

### Data Flow Diagram
```text
[Conversations] ---> [Ingestion API] ---> MySQL (conversations)
                                           |
[Fact Extractor] --> [LLM Evaluator (GPT-4o)] --> 4 dimensions scored in one call
      |
      v
  MySQL (evaluations) ---> [Pattern Detector / Regression Detector]
                                           |
[Human Annotations] ---> [Meta-Calibration + Blind Spots] -> MySQL (meta_evaluations/drift_corrections)
                                           |
                              [React Dashboard (eval-ui)]
```

## Quick Start
To launch the entire platform, including the database, API server, and React UI using Docker, simply run:
```sh
docker-compose up --build
```
The API will be available at `localhost:3000` and the UI dashboard at `localhost:5173`.

## Manual Setup
If you want to run the project locally without Docker:
1. Ensure MySQL is running on port 3306.
2. Install backend dependencies: `cd eval-pipeline && npm install`
3. Install frontend dependencies: `cd eval-ui && npm install`
4. Initialize Database: `npm run db:init`
5. Seed Data: `npm run db:seed`
6. Start Node API: `npm start`
7. Start Worker: `npm run worker`
8. Start React UI: `cd ../eval-ui && npm run dev`

## API Documentation

### Conversations
- **GET** `/api/conversations`
  - Res: `{ conversations: [...], total, limit, offset }`
- **GET** `/api/conversations/:id`
  - Res: `{ id, agent_version, turns, feedback, metadata ...}`
- **POST** `/api/conversations`
  - Req Body: `{ conversation_id, agent_version, turns: [...], feedback: {}, metadata: {} }` or Array.
  - Res: `{ ingested, errors }`
- **GET** `/api/conversations/:id/stats`
  - Res: `{ turn_count, user_turns, assistant_turns, tool_call_count, tool_success_rate, user_rating, mission_completed, total_latency_ms }`

### Evaluations
- **GET** `/api/evaluations`
  - Query: `?limit=&offset=&min_score=&max_score=`
  - Res: `{ evaluations: [...], total, limit, offset }`
- **GET** `/api/evaluations/:conversation_id`
  - Res: `[{ id, scores, tool_evaluation, issues_detected, improvement_suggestions, review_routing ... }]`
- **POST** `/api/evaluations/:conversation_id`
  - Query: `?realtime=true` for synchronous response (default is async via job queue)
  - Res (realtime): `{ id, scores, review_routing, tool_evaluation, issues_detected, improvement_suggestions }`
  - Res (async): `{ job_id, status: "pending", message }`
- **POST** `/api/evaluations/batch`
  - Req Body: `{ agent_version: "v1.0" }` or `{ conversation_ids: [...] }`
  - Query: `?realtime=true` for synchronous response
  - Res: `{ evaluated, results, errors }`

### Feedback / Annotations
- **GET** `/api/feedback/:conversation_id`
  - Res: `[{ id, label, type ... }]`
- **POST** `/api/feedback`
  - Req Body: `{ conversation_id, annotator_id, annotation_type, label, confidence, notes }`
  - Res: `{ NEW_ANNOTATION_OBJECT }`

### Meta & Calibration
- **GET** `/api/meta/calibration?evaluator_type=&days=`
  - Res: `{ total_comparisons, agreement_rate, avg_eval_score, avg_human_score, drift }`
- **GET** `/api/meta/drift?threshold=0.15`
  - Res: `[ { evaluator_type, drift, alert } ]`
- **POST** `/api/meta/calibrate/:conversation_id`
  - Res: `{ evalScore, avgHumanScore, agreement }`
- **GET** `/api/meta/disagreements`
  - Res: `[ { conversation_id, disagreements: [ ... ] } ]`
- **POST** `/api/meta/disagreements/resolve`
  - Req Body: `{ conversation_id, annotation_type, resolved_label, resolver_id }`
  - Res: `{ NEW_RESOLVED_ANNOTATION }`
- **GET** `/api/meta/accuracy?days=`
  - Res: `{ per_category: [{ annotation_type, eval_dimension, tp, fp, fn, tn, precision, recall, f1, total }], overall: { precision, recall, f1 }, total_comparisons }`
- **GET** `/api/meta/blind-spots?days=&threshold=0.7`
  - Res: `{ blind_spots: [{ category, eval_dimension, miss_count, miss_rate, severity, sample_conversation_ids ... }], total_annotations_analyzed }`
- **POST** `/api/meta/corrections?threshold=0.15`
  - Res: `{ corrections: [{ evaluator_type, correction_factor, drift, direction, recommendation, sample_size }], threshold }`
- **GET** `/api/meta/corrections?evaluator_type=`
  - Res: `{ evaluator_type, correction_factor }`

### Regressions
- **GET** `/api/meta/regressions?current=v2.0&previous=v1.0`
  - Res: `[ { metric, current_avg, previous_avg, delta, is_regression } ]`

### Suggestions
- **GET** `/api/suggestions`
  - Query: `?type=prompt|tool&status=pending|accepted|rejected|applied&limit=`
  - Res: `[ { id, type, suggestion, status... } ]`
- **POST** `/api/suggestions/generate`
  - Query: `?realtime=true&days=7`
  - Res (realtime): `{ prompt_suggestions: [...], tool_suggestions: [...] }`
  - Res (async): `{ job_id, status: "pending", message }`
- **PATCH** `/api/suggestions/:id`
  - Req Body: `{ status: "accepted" }`
  - Res: `{ UPDATED_SUGGESTION }`

### Jobs
- **GET** `/api/jobs`
  - Query: `?type=&status=&limit=`
  - Res: `[ { id, type, status, created_at, started_at, completed_at } ]`
- **GET** `/api/jobs/:id`
  - Res: `{ id, type, status, result, error, created_at, started_at, completed_at }`

## Design Decisions
- **Raw Queries vs ORM**: Parameterized queries using `mysql2` explicitly prevent abstraction overhead and optimize performance for deeply nested structured evaluations, offering unparalleled control.
- **Why MySQL**: Best-in-class structure for indexing complex datasets with rich JSON manipulation natively available.
- **Single GPT-4o Call**: All four evaluation dimensions are scored in a single LLM call, reducing latency and cost compared to 4 separate calls. Objective facts are extracted first (factExtractor.js) and injected into the prompt so the model has full context.
- **Drift Auto-Correction**: When evaluator scores drift from human consensus, correction factors are computed and automatically applied to future evaluation scores, closing the meta-evaluation flywheel.

## Scaling Strategy
- **Handling 10x**:
  - Implement read-replicas for `GET` analytics.
  - Implement asynchronous queue scheduling (RabbitMQ/Bull) to defer evaluation workloads on insertion.
- **Handling 100x**:
  - Distribute logs into a data stream (e.g., Apache Kafka or Kinesis) directly serving ingestion microservices.
  - Deploy standalone evaluator worker clusters independently communicating with GPT-4o.
  - Apply Redis caching instances for highly frequent read metrics.

## Trade-offs
- Heavily optimized for speed and deployment simplicity (raw connections, standalone Node.js) over strict TypeScript schemas and enterprise ORM.
- Evaluation APIs fail gracefully handling empty values if API endpoints timeout or rate limit rather than stalling pipelines.
- MySQL-as-queue pattern (jobs table) avoids needing a separate broker for the prototype, but should be replaced with Redis/RabbitMQ at scale.
